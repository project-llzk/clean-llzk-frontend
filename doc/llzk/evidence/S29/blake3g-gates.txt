BLAKE3.G external discriminator
-------------------------------

All six BLAKE3.G indices 0 through 5 ran through both LLZK witness backends in
both full-witness and public scopes. The dedicated lane-marker index 5 has an
exact carrier of 72 ordered inputs, 96 w{k} cells, and 64 out{j} values.

For each backend, the real accepted tool first accepted one full and one public
baseline, then rejected:

  96 isolated canonical one-cell witness mutations in full scope;
  64 isolated canonical one-member output mutations in full scope; and
  64 isolated canonical one-member output mutations in public scope.

That is four green baselines plus 448 isolated real-tool red mutations across
both backends. They are one marker row's one-field mutations, not 448 vectors,
input mutations, arbitrary corruptions, or constraint executions. Inputs are
checked for exact arg0..arg71 layout, canonicality, and full-input association,
but are not individually perturbed. Witness cells do not exist in public scope.

G11 separately uses an all-ones synthetic carrier, 1-to-0 mutations, a
content-aware checker, and an exact 452-call log: four baselines plus the same
448 backend/scope/key targets. It demonstrates that
a checker ignoring w42 is caught, that every positive count drives validation,
that exact arity includes the empty-tenth/nonempty-eleventh bypass, and that
canonicality controls reach their intended branches. It also digest-pins the
whole e2e driver. One reachability mutation inserts an early continue that makes
the six vector preflights unreachable; the other wraps the entire BLAKE
discriminator block in an outside false conditional. The whole-file digest gate
rejects both. This synthetic log is a harness falsification proof; it is not the
real-tool mutation evidence above.

BLAKE3G is admitted to the product-program pipeline. Its SMT lowering is a
declared skip because felt.uintdiv/felt.umod are illegal for the current pass;
that is a measured tool limitation, not a semantic conclusion.
